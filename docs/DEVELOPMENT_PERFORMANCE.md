# 개발 작업의 CPU 사용

## 기본 제한

- Vitest 일반 테스트는 최대2워커, MEASURE=1 시뮬레이션은 최대1워커.
- 필요할 때 전용 머신에서 `pnpm test --maxWorkers=4`처럼 명시적으로 조정한다.
- 여러 워크트리에서 빌드·전체 검사·물리 측정을 동시에 실행하지 않는다.
- 변경 관련 검사 후 마지막에 필요한 전체 검사를 한 번 실행한다. 새 변경/실패가 없으면 같은 검사를 반복하지 않는다.
- 브라우저 검증은 사용한 브라우저를 finally에서 닫는다. 검증 전용 서버는 종료 시 함께 정리한다.
- 문서만 변경한 커밋은 공백 검사만 한다. docs의 Markdown과 루트 README/CHANGELOG에 한정하며 혼합 변경은 기존 검사로 진행한다.
- 커밋 스냅샷에도 .oxlintrc.json을 포함해 평소와 같은 린트 설정을 사용한다.

## 스토리 화면

스토리는 게임 화면 전체를 덮는다. 그동안 엔진 update뿐 아니라 render도 건너뛰어 물리 스냅샷 생성과 숨은 WebGL 그리기를 하지 않는다.
스토리를 닫으면 다음 프레임부터 정상 렌더링한다. 테스트에서 draw 호출0 및 종료 후 재개를 확인한다.

## 단일 비교 기록

동일 머신에서 `/usr/bin/time -p pnpm test`를 변경 전후 한 번씩 실행했다.

| 항목 | 변경 전 | 워커 제한 후 |
| --- | --- | --- |
| 테스트 | 1108 통과 | 1109 통과 (렌더링 재개 검사 추가) |
| wall | 9.71초 | 13.48초 |
| user+sys CPU | 42.23초 | 37.41초 |

CPU 누적 시간 약11% 감소, 완료 대기시간 약39% 증가. 다른 앱이 실행 중인 단일 표본이라 보편적인 성능 보장은 아니다.
목적은 최단 완료 시간이 아니라 작업 중 동시 CPU 부하를 제한하는 것이다.
외부 앱·시스템 프로세스는 이 저장소 최적화 범위에 포함하지 않았다.
