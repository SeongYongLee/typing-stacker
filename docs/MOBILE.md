# 모바일 플레이 지원 계획

작성일: 2026-09-07
상태: 모바일 메뉴와 싱글플레이를 정식 화면 흐름에 연결했다. 배포 및 실기 키보드 검증은 별도다.

## 현재 구현

- 조작 방식은 자동·PC·모바일 중 선택해 저장한다. 자동은 터치 중심 환경을 모바일로, 정밀 포인터와 호버가 있는 환경을 PC로 판단한다. PC는 800px 이상에서 기존 좌우 배치를 유지하고, 800px 미만에서만 간결한 싱글 배치를 쓰되 PC의 Enter·Esc 조작을 유지한다. 선택 변경은 다음 게임부터 적용한다.
- 메인 메뉴에 PC 플레이 권장 문구와 펼쳐 보는 점수 순위를 표시한다. 함께 하기는 PC 전용으로 비활성화한다.
- 프로필 화살표는 44px 터치 영역, 도감은 좁은 폭에서도 두 열, 옵션은 목록 스크롤과 고정 돌아가기를 사용한다.
- 결과 패널은 화면 폭과 높이에 맞춘다. 내용은 함께 스크롤하고 하단 버튼은 고정한다. 모바일에서는 메뉴 안내를 터치·스크롤 문구로 바꾼다.
- 모바일 게임은 App의 엔진과 저장·소리·결과 흐름을 공유한다. 첫 시작·재시작에서는 입력창의 “눌러서 시작”을 눌러 키보드를 연다. 화면 높이가 안정된 뒤 게임을 진행하며, 실제 일시정지·앱 전환 후에만 자리 비움 창을 표시한다. 튜토리얼 설명은 게임 위 별도 영역에서 설명 단계에는 하단 입력칸을 대신하는 ‘다음’ 버튼으로 넘기며 입력 포커스를 유지한다. 단어 놓기·회수는 키보드의 입력 버튼으로 진행하고, 빈 Enter로 설명을 넘기는 동작도 유지한다.
- PC·모바일은 쌓기→합성→회수→경보→마무리의 공통 안내를 사용한다. 합성 뒤 바로 회수하며, 회수 성공 안내에서 경보 시연으로 이어진다. 모바일 하단 버튼과 PC Enter 안내는 현재 행동에 맞춰 표시한다.
- `?mobile-play=1` 연습 엔진과 비교 화면은 개발 환경에서만 유지한다.

아래는 최초 검토 당시의 계획과 제약이다.

가독성 시제품 결과: [검증 보고서](mobile-readability/README.md). 기존 카메라로 단어를 상단에 모으면 물건이 너무 작아진다. 화면 기반 구현 전에 모바일 카메라와 단어 영역을 재검증한다. 실제 키보드 검증은 아직 남아 있다.

## 목표와 범위

물리 키보드 없이 게임 진입 → 튜토리얼 → 플레이 → 일시정지 → 결과 → 재시작을 완료한다.
단어를 입력하고 제출한 순간에 물건을 놓는 기존 조준 규칙을 유지한다.

- 1차: 세로 화면의 싱글플레이, 닉네임 설정, 옵션, 도감, 결과 화면.
- 목표 화면 폭: 360~430 CSS px. 태블릿과 기존 데스크톱도 함께 확인한다.
- 가로 화면: 공간이 부족하면 싱글을 멈추고 세로 전환을 안내한다. 회전으로 세션을 초기화하지 않는다.
- 후속: 모바일 멀티플레이의 로비·채팅·대전 화면과 입력 방식별 경쟁 균형 검토.
- 모바일에서 후속 기능은 지원 상태를 안내해 사용할 수 없는 화면으로 진입하지 않게 한다.
- 초기에는 물리·점수·단어 수명·난이도 규칙을 유지한다. 실기 플레이에서 문제가 확인되면 별도로 조정한다.

## 최초 검토 당시 제약

- `Root.tsx`가 폭 1200px 미만에서 App을 만들지 않는다. 경계를 넘으면 App이 언마운트된다.
- `GameScreen.tsx`의 3열 배치는 최소 676px이 필요하다.
- `ArenaRenderer.resize()`는 폭뿐 아니라 높이로도 물건 크기를 제한한다.
- `index.css`는 전체 높이를 100svh로 고정하고 body 스크롤을 막는다.
- `useHangulInput.ts`는 Enter keydown으로 제출하며 조합 후 입력 차단 해제도 keydown에 의존한다.
- `MemoInput`의 자동 포커스와 게임 시작 후 포커스 호출에는 모바일 키보드 준비 과정이 없다.
- 싱글 일시정지는 Escape에 의존하고 튜토리얼에도 빈 Enter를 기다리는 단계가 있다.

## 1. 화면과 입력 검증용 시제품

가장 먼저 해결할 질문은 “가상 키보드를 연 채 단어, 조준점, 쌓인 물건을 읽을 수 있는가”다.

- 상단에 점수·혼잡 상태·일시정지, 중앙에 단어와 아레나, 키보드 바로 위에 입력창·놓기 버튼을 배치한다.
- 단어 영역을 상단에 모으는 안을 먼저 검증한다. 현재 제출 가능한 단어, 놓침까지의 진행 상태, 합성·회수 표식을 보존한다.
- 단어가 많은 상황과 긴 단어로 확인한다. 공간 확보를 위해 제출 가능한 단어를 숨기지 않는다.
- 아레나를 과도하게 축소하지 않도록 단어 영역 높이와 장식·보조 정보의 비중을 조정한다.
- iOS Safari와 Android Chrome에서 실제 한글 키보드를 열고 확인한다. 에뮬레이션은 배치 확인에만 사용한다.

완료 기준: 목표 화면에서 단어를 읽고 조준해 연속 제출할 수 있는 배치와 키보드 이벤트 경로를 확인한다.
이 검증 결과로 상세 치수와 모바일 카메라 조정 필요 여부를 결정한 뒤 다음 단계로 진행한다.

## 2. 모바일 화면 기반

주요 대상: `Root.tsx`, `useViewport.ts`, `index.css`, `GameScreen.tsx`, `TypingLane.tsx`, `StackArena.tsx`, `ArenaRenderer.ts`.

- 1200px 전체 진입 차단을 화면별 반응형 배치와 지원 안내로 교체한다.
- 화면 크기가 변해도 App과 엔진 인스턴스를 유지한다.
- 모바일 전용 스타일을 분리하고 기존 게임 상태·물리 엔진을 공유한다.
- 키보드와 브라우저 UI를 제외한 실제 가시 영역에 플레이 화면을 맞춘다. 노치와 홈 인디케이터 여백도 처리한다.
- 게임 화면은 입력창과 핵심 플레이 영역을 동시에 유지하고, 메뉴·도감·옵션은 필요한 경우 스크롤을 허용한다.
- 캔버스 크기 변경 시 조준점·물건·단어 표시가 맞는지 확인한다. 빈 높이나 회전 중간값도 처리한다.

완료 기준: 키보드 열기·닫기, 주소창 변화, 화면 회전에도 가림·가로 넘침·게임 초기화가 없다.

## 3. 터치와 한글 입력

주요 대상: `useHangulInput.ts`, `InputBar.tsx`, `App.tsx`, `SoloGameScreen.tsx`.

- 물리 Enter와 화면의 놓기 버튼이 하나의 제출 경로를 사용하게 한다.
- 조합 중 마지막 글자 누락, 중복 제출, 제출 후 글자 부활, 다음 단어 입력 소실을 처리한다.
- 키다운이 없는 입력 흐름도 다룰 수 있도록 조합 정리 상태를 설계한다.
- 놓기 버튼을 눌러도 키보드가 불필요하게 닫히지 않게 한다. 자동 수정·자동 완성으로 제출 문자열이 변하는지도 확인한다.
- 입력 준비 동작에서 키보드를 열고 사용자가 준비된 뒤 게임을 진행한다. 포커스 실패 시 입력창을 직접 누를 수 있다.
- 키보드 닫기와 입력 포커스 이동을 구분한다. 입력할 수 없는 상태의 싱글은 일시정지하고 명시적인 재개를 제공한다.
- 화면을 벗어났다가 돌아왔을 때도 자동 진행으로 손해 보지 않도록 일시정지 흐름을 확인한다.

완료 기준: 실제 한글 키보드로 조합 중 제출, 연속 단어, 삭제·재입력, 오답, 빠른 연타를 처리하며 의도한 제출당 엔진 호출이 한 번 발생한다.

## 4. 전체 게임 흐름

주요 대상: 타이틀·이름·규칙·일시정지·결과·옵션·도감 화면과 튜토리얼 안내.

- 터치로 시작·재개·다시 하기·홈 이동을 완료한다.
- 빈 Enter가 필요한 튜토리얼 단계에 다음 버튼을 제공한다. 일반 플레이의 빈 입력 제출은 계속 무시한다.
- 모바일 안내를 실제 버튼 이름과 일치시키고 물리 키보드 안내도 유지한다.
- 자주 쓰는 터치 버튼의 목표 크기는 최소 44×44 CSS px로 잡는다.
- 긴 닉네임, 결과 정보, 도감 상세, 옵션의 하단 버튼이 잘리지 않도록 확인한다.

완료 기준: 첫 방문부터 튜토리얼 완료·일반 플레이·게임오버·재시작까지 물리 키보드가 필요 없다.

## 5. 검증과 적용

- 자동 검증: 한글 조합·제출 이벤트 순서에 대한 회귀 테스트, 화면 크기 변경 시 세션 유지, 튜토리얼 다음 동작.
- 브라우저 검증: 360/390/430px 세로, 태블릿, 1200px 이상 데스크톱의 진입·배치·터치 흐름.
- 실기 검증: iOS Safari의 한글 키보드, Android Chrome의 Gboard 또는 삼성 키보드. 가능하면 두 Android 키보드를 모두 확인한다.
- 실기에서 키보드 높이 변화, 앱 전환, 회전, 연속 입력, 혼잡·다중 합성 연출이 있는 장면을 확인한다.
- 데스크톱 Enter 1회 제출, IME 정리, Escape 일시정지, 기존 멀티플레이를 회귀 확인한다.
- 프레임 시간과 입력 반응을 측정한다. 부족하면 렌더 해상도·장식 효과부터 조정하고 게임 규칙 변경과 분리한다.
- 최종 변경에 맞는 테스트·타입 검사·린트·빌드를 실행한다. 기존 `Viewport.test.ts`의 데스크톱 전용 제한도 새 지원 정책에 맞춰 수정한다.
- 실제 기기 검증이 불가능하면 해당 항목을 미검증으로 남기고 모바일 지원 완료로 판단하지 않는다.

## 작업 순서와 완료 정의

시제품 검증 → 화면 기반 → 입력 처리 → 전체 흐름 → 실기·회귀 검증 순서로 진행한다.
화면 제한 해제만 따로 출시하지 않고 싱글 전체 흐름이 동작하는 단위로 적용한다.

완료 조건은 지원 대상의 실제 휴대폰에서 키보드를 연 채 튜토리얼과 일반 게임을 플레이하고,
중복·누락 없이 연속 제출하며, 중단·재개·재시작할 수 있고, 기존 데스크톱 동작도 유지되는 것이다.

멀티플레이는 이 기반을 재사용하되 로비·채팅·대전의 화면 공간과 가상 키보드 사용성을 별도로 검증한 후 확장한다.
