# 멀티플레이 대결

현재 멀티플레이는 참가자마다 별도 받침대를 쓰는 **개인 생존전**이다. 모두 동시에 자기 단어를 입력하고, 합성으로 상대 필드에 물건을 보내며, 마지막까지 하트가 남은 한 명이 승리한다. 회수 목표·목표 높이·화이트보드 하트 회복은 대전 규칙에 없다.

현재 로비 모드는 `대결`로 고정되어 있다. 자동 매칭은 2명을 연결하고, 코드 방은 같은 규칙을 여러 참가자에게 적용한다. 프로토콜 상한은 8명이다.

## 한 판의 흐름

1. 전원이 준비하면 방장이 새 시드를 정하고 카운트다운을 시작한다.
2. 시드로 싱글 스테이지 1~5 중 하나를 고른다. 튜토리얼 스테이지 0은 제외한다.
3. 스테이지 이름과 제한된 단어 풀을 모든 참가자가 공유한다.
4. 각 참가자는 자기에게 배정된 단어를 동시에 입력해 자기 필드에 물건을 놓는다.
5. 자기 필드에서 재료가 합쳐지면 먼저 예약 공격을 상쇄하고, 남은 공격을 다음 생존자에게 보낸다.
6. 물건이 필드 밖으로 나갈 때마다 하트가 줄고, 하트가 0이 되면 탈락한다.
7. 한 명만 남으면 그 참가자가 1위다. 같은 판정에서 함께 탈락하면 공동 순위가 될 수 있고 모두 탈락하면 무승부다.

## 스테이지와 단어 풀

스테이지는 경기 시드만으로 결정하므로 재접속하거나 방장이 바뀌어도 같은 이름과 풀을 복원할 수 있다. 화면 상단에는 선택된 스테이지 이름을 경기 내내 표시한다.

단어 풀에는 해당 싱글 스테이지의 `featuredWords`, 태그에 맞는 단어, 보장할 히든 합성의 재료 단어가 들어간다. 단순 무작위만 쓰지 않고 참가자별 `RecipeFlow`를 번갈아 적용해 각 필드에서 필요한 합성 재료가 이어지도록 한다.

선택한 스테이지에서 가져오는 것은 **이름과 단어 구성**이다. 생성 속도·낙하 속도는 스테이지의 싱글 난이도를 복사하지 않고, 멀티 전체 탑 높이와 참가자 수로 계산한다. 대결에서는 단어 공급을 기본 멀티 난이도의 2배로 하고 화면 최대 동시 단어 수까지 허용한다.

## 단어 소유와 낙하

단어 목록은 방장이 하나만 생성해 배포한다. 단어 ID를 참가자 순서에 순환 배정하고, 각 화면에는 자기 소유 단어만 보여준다. 남의 단어를 입력해 상대의 제한시간을 없앨 수 없도록 실제 드롭 요청도 방장이 소유권을 다시 검증한다.

- 참가자는 차례를 기다리지 않고 동시에 입력한다.
- 직접 입력한 뒤에는 참가자별로 0.5초의 드롭 쿨타임이 돈다.
- 승인된 드롭은 약 100ms 뒤의 공통 물리 tick에 예약해 네트워크 도착 차이를 흡수한다.
- 고정된 개인 잠수 타이머는 없다. 자기 단어가 바닥에 닿는 순간이 그 단어의 제한시간이다.
- 놓친 단어는 첫 번째 기본 변형 물건으로 자기 필드에 자동 낙하한다.
- 자동 낙하와 공격 낙하는 직접 입력 쿨타임을 막지 않는다.

## 합성과 예약 공격

자기 필드의 접촉 그래프가 레시피를 만족하면 재료를 합치고 합성 결과물과 보조 발판을 만든다. 공격 수는 `max(1, 재료 수 - 1)`이다.

합성 공격은 뿌요뿌요처럼 즉시 떨어지지 않고 다음 순서로 처리한다.

```text
합성
→ 내가 받을 예약 공격부터 상쇄
→ 남은 수를 다음 생존자에게 예약
→ 1.2초 예고
→ 공격받는 사람의 다음 물건 배치 대기
→ 그 물건의 정착·합성 판정 대기
→ 새 합성으로 예약 공격 상쇄
→ 남은 공격을 0.28초 간격으로 낙하
```

예약 공격 상태는 화면 상단에 다음 네 단계로 보인다.

| 상태 | 화면 안내 | 의미 |
|---|---|---|
| `warning` | `N초 후 방어 기회` | 1.2초 예고 중 |
| `waiting` | `물건을 하나 놓아 방어` | 예고 뒤 첫 배치를 기다림 |
| `checking` | `합성 확인 중` | 방어 물건이 정착하고 합성될 때까지 기다림 |
| `dropping` | `낙하 중` | 상쇄되지 않은 공격을 순차 낙하 |

방어 물건은 **예고가 끝난 뒤** 직접 입력하거나 단어 만료로 자동 낙하한 첫 물건이다. 예고 중 미리 놓은 물건과 공격으로 떨어진 물건은 방어 배치가 아니다. 방어 물건이 자리 잡는 동안 자기 필드에서 합성이 완성되면 그 공격량만큼 예약분을 지운다. 합성 공격량이 예약분보다 크면 초과분은 다음 생존자에게 넘어간다.

상쇄되지 않은 공격은 현재 스테이지 단어 풀에서 기본 변형을 하나 골라 대상 필드의 무작위 가로 위치에 떨어뜨린다. 이미 낙하를 시작한 묶음도 이후 합성으로 남은 수를 줄일 수 있다.

## 탈락과 승패

- 시작 하트는 3개다.
- 자기 소유 물건이 필드 밖으로 나가면 하트가 1개 줄어든다.
- 한 번 무너진 탑에서 물건이 연달아 이탈해 즉사하지 않도록 피격 후 2초간 무적을 준다.
- 하트가 0이면 해당 타워를 탈락 처리하고 순위를 뒤에서부터 확정한다.
- 마지막 생존자를 1위로 확정하고 판을 끝낸다.
- 연결 유예가 끝나 실제로 나간 참가자도 탈락으로 처리한다.

## 권위와 동기화

중계 서버는 메시지를 전달할 뿐 게임 규칙을 판정하지 않는다. 한 클라이언트가 방장이 되어 공용 상태의 권위를 갖는다.

- **방장:** 단어 생성, 입력·단어 소유 검증, 예약 공격, 하트, 탈락, 순위, 승자를 판정한다.
- **각 참가자:** 자기 필드의 물리를 계산하고 약 0.125초마다 `duelBoardState`를 보낸다.
- **방장:** 받은 필드 상태에서 합성·이탈 보고를 검증해 공격과 생존 판정에 반영한 뒤 다른 참가자에게 중계한다.
- **모든 참가자:** `duelAttacks`, `duelResults`, `lives`, `words`의 방장 스냅샷을 따른다.

필드별 tick을 기록해 늦게 온 상태가 게임판을 되감지 못하게 하고, 렌더링에서는 짧은 위치 보정으로 네트워크 스냅이 눈에 띄지 않게 한다. 새 방장이 되거나 재접속한 참가자가 생기면 현재 단어·하트·결과·공격·물리 상태를 다시 선언한다.

## 중계 서버 실행

대전은 **중계 서버를 거쳐** 붙는다.

```bash
pnpm relay:dev                                    # 로컬 중계 (localhost:8787, wrangler를 그때 받아온다)
VITE_RELAY_URL=ws://localhost:8787 pnpm dev       # 앱이 그 중계를 쓰게 한다

pnpm relay:deploy                                 # Cloudflare에 올린다 (wrangler login 필요)
```

## 왜 P2P를 지웠나

처음에는 WebRTC로 직접 붙였는데, NAT을 통과해야만 동작하는 구조라 같은 Wi-Fi의 두 기기조차 못 붙는 경우가 있었다 — 공유기가 멀티캐스트를 막으면 Chrome이 가려둔 mDNS 후보를 상대가 풀지 못하고, 같은 공인 IP 뒤라 헤어핀 NAT까지 필요하다. 그 구멍을 메우는 TURN은 공용 무료 서버가 더 이상 없다(peerjs·openrelay 모두 사라졌고, 각각 몇 시간씩 원인을 찾은 뒤에야 알았다).

중계는 그 조건을 통째로 없앤다. 양쪽 모두 **바깥으로 나가는 WebSocket 하나**만 열면 되고 그건 어떤 망에서도 열린다. 그래서 **P2P 경로는 남겨두지 않고 지웠다** — 어차피 붙지 않는 길을 대비책으로 두면 실패했을 때 "중계가 죽은 것"과 "P2P로 떨어진 것"을 구분하느라 시간만 쓴다.

## 중계 주소는 소스에 적혀 있다

비밀이 아니라서 — 어차피 클라이언트 번들에 실려 나간다 — 숨기지 않는다. 빌드 설정에 숨겨두면 저장소를 새로 받은 사람이 "왜 대전이 안 되지"를 코드에서 찾을 수 없다.

## 방 하나가 Durable Object 하나다

`worker/`에 있다. 같은 코드는 언제나 같은 인스턴스로 가므로 방을 찾는 절차가 필요 없고, 전송로는 `Transport` 인터페이스 뒤에 있어 게임 코드는 무엇으로 붙었는지 모른다 — 그래서 시험용 루프백으로 갈아끼워 서버 없이도 판 전체를 자동 검증한다.

## 변경할 때 지켜야 할 계약

- 단어 소유권, 드롭, 공격, 하트와 승패를 참가자마다 따로 판정하지 않는다. 방장 판정 하나를 공유한다.
- 공격 예고가 끝났다는 이유만으로 바로 낙하시키지 않는다. 대상의 다음 배치와 합성 확인을 반드시 거친다.
- 공격 드롭을 다시 방어 배치로 세지 않는다. 공격이 공격을 무한히 지연시키게 된다.
- 선택 스테이지의 싱글 `returnTarget`이나 화이트보드 규칙을 대전에 연결하지 않는다.
- `goal`, `duelWhiteboard`, 하트 회복 메시지는 생존전 프로토콜에 다시 추가하지 않는다.
- 필드 주인이 아닌 참가자가 보낸 `duelBoardState`를 그대로 신뢰하지 않는다.

검증은 최소한 다음을 실행한다.

```bash
pnpm test
pnpm typecheck
pnpm lint
pnpm build
```
