# 3D 플레이 성능 점검

모바일 390×780, DPR 3, Chrome 개발 서버, CPU 4배 감속 조건에서 측정했다. 실기기나 프로덕션 FPS 보장은 아니다.

- 정지 물건 60개, 물리 연산을 분리한 비교: 그리기 호출 139→72회/프레임, JS 그리기 평균 4.15→2.93ms, p95 5.9→4.0ms.
- 변하지 않은 화이트보드·혼잡도·합성 알림 컴포넌트를 재사용한다. 시계·단어·물리 루프 속도는 유지한다.
- 그림자 지도는 물건 추가/제거/이동/회전/젤리/회수/상자 변경/흔들림 때 갱신한다. 정지 상태는 재사용한다.
- 모바일 캔버스 DPR 상한 2→1.5(같은 CSS 크기에서 픽셀 약 44% 감소), 그림자 지도 1024→512. 데스크톱 해상도는 유지한다.
- 회수 손 캔버스는 손이 보이는 동안과 사라지는 첫 프레임만 갱신한다.
- 0.5초 간격 실제 낙하 검사: 프레임 간격 p95 16.7ms, 물리 step 평균 1.69ms, 그리기 평균 2.61ms.
- 60개를 처음부터 겹쳐 놓은 극한 조건에서는 물리 step 평균 63.6ms / p95 184.5ms였다. 충돌 규칙과 시간 진행을 임의로 바꾸지 않았으며, 이 조건의 물리 병목은 남아 있다.

재현: `scripts/profile-game-rendering.mjs`, 캐시 유효성: `scripts/check-render-cache.mjs`. 캐시 검사는 정지/이동의 그리기 호출, 손 캔버스 정리, 모바일 해상도를 실제 WebGL에서 확인한다.
