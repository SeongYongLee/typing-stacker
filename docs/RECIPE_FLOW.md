# 레시피 중심 스폰과 화이트보드

이 문서는 싱글플레이의 단어 선택 정본이다. `RecipeFlow`가 어떤 레시피를 집중하는지, 화이트보드가 그 흐름과 충돌하지 않도록 어떤 순서로 갱신되는지, `WordSpawner`가 최종 단어를 어떻게 고르는지를 함께 설명한다.

관련 코드:

- `src/game/systems/RecipeFlow.ts`
- `src/game/systems/Whiteboard.ts`
- `src/game/systems/WordSpawner.ts`
- `src/game/core/GameEngine.ts`
- `tests/RecipeFlow.test.ts`
- `tests/Whiteboard.test.ts`
- `tests/Recall.test.ts`
- `tests/zz-recipe-flow.measure.test.ts`

## 지켜야 하는 규칙

1. **집중 레시피를 화이트보드보다 먼저 정한다.**
2. **현재 집중 레시피에서 타이핑으로 낼 수 있는 재료 단어는 화이트보드 후보에서 제외한다.**
3. 첫 밤에는 화이트보드를 닫는다.
4. 낮과 밤에는 107개 단어를 모두 열어 두되, RecipeFlow가 레시피 재료의 간격을 조절한다.
5. 화이트보드 우선 스폰이 끼어들어도 RecipeFlow의 집중 레시피와 제안 횟수는 진행시키지 않는다.
6. 같은 시드와 같은 관측 상태는 같은 RecipeFlow 순서를 만든다.
7. 이 흐름은 싱글플레이에만 적용한다. 대전은 RecipeFlow 상태를 동기화하지 않으므로 기존 랜덤 스폰을 유지한다.

핵심 순서는 다음과 같다.

```text
현재 물건 관찰
→ 집중 레시피 확정
→ 집중 재료를 제외하고 화이트보드 보충
→ 화이트보드 추가 가중치 추첨
→ 미당첨이면 RecipeFlow가 단어 선택
→ 레인에 스폰
```

## 모듈의 책임

### RecipeFlow

현재 집중할 레시피와 그 레시피에서 더 필요한 재료를 정한다.

- 레시피 44개를 직접 레시피 34개와 연쇄 레시피 10개로 분류한다.
- 직접 레시피는 기본 단어만으로 완성할 수 있다.
- 연쇄 레시피는 다른 합성 결과물이 판에 있어야 집중 후보가 된다.
- 직접 레시피의 재료가 아닌 단어는 ambient 무리에 둔다.
- 현재 재료 개수는 외부에서 주입받고 DOM, canvas, Rapier를 직접 알지 않는다.

### Whiteboard

현재 보드에 적힌 최대 3개의 회수 단어를 관리한다.

- 주어진 단어 밭 안에서만 채운다.
- 이미 유효한 보드 항목은 유지한다.
- 밭을 벗어났거나 `excluded`에 포함된 항목만 교체한다.
- 회수한 단어는 한 칸을 비운 뒤 같은 밭과 제외 목록으로 즉시 보충한다.
- 어떤 단어가 레시피 재료인지는 알지 않는다. 제외 목록은 GameEngine이 넘긴다.

### WordSpawner

좌우 레인, 중복 방지, 스폰 간격과 최종 선택 순서를 관리한다.

싱글의 선택 우선순위는 다음과 같다.

```text
화이트보드 추가 가중치
→ RecipeFlow.pick()
→ 최후의 기본 랜덤
```

대전에는 RecipeFlow 선택기를 주입하지 않으므로 기존 랜덤 선택을 유지한다.

### GameEngine

세 시스템을 시간순으로 조립한다.

- 물리 세계, 활성 단어, 드롭 대기열을 세어 RecipeFlow에 전달한다.
- RecipeFlow가 집중 레시피를 먼저 확정하게 한다.
- 집중 재료 단어를 Whiteboard의 제외 목록으로 넘긴다.
- Whiteboard의 현재 단어를 WordSpawner의 선호 목록으로 넘긴다.
- 회수 드롭은 RecipeFlow가 보는 재료 개수에서 제외한다.

## RecipeFlow의 분류와 선택

### 직접·연쇄·ambient

| 무리 | 현재 구성 | 의미 |
|---|---:|---|
| 직접 레시피 | 34개 | 모든 재료가 기본 단어로 존재한다 |
| 연쇄 레시피 | 10개 | 입력 중 하나 이상이 다른 합성 결과물이다 |
| 직접 재료 | 65종 | 직접 레시피가 집중할 수 있는 기본 단어 |
| ambient | 42종 | 비레시피 28종 + 연쇄 레시피에서만 쓰이는 기본 재료 14종 |

ambient에 연쇄 레시피의 기본 재료도 넣는 이유는 선행 합성 결과물이 없을 때도 모든 단어가 계속 등장해야 하기 때문이다.

### 국면별 밀도

| 국면 | 종료 조건·길이 | RecipeFlow 선택 |
|---|---|---|
| 첫 밤 | 합성 2회 또는 상한 35초 | 2재료 레시피 집중, 레시피 선택 2회마다 ambient 1회 |
| 낮 | 20초 | 레시피 선택 2회마다 ambient 1회 |
| 밤 | 10초 | 레시피 선택 3회마다 ambient 1회 |

국면은 낙하 속도를 바꾸지 않는다. 밤은 레시피 선택 사이의 ambient 간격만 늘린다.

### 첫 밤의 레시피 순서

첫 밤은 모든 직접 2재료 레시피를 대상으로 하되 두 셔플백을 번갈아 쓴다.

```text
같은 재료 둘인 쉬운 조합
→ 서로 다른 재료 둘인 조합
→ 같은 재료 둘인 쉬운 조합
→ 서로 다른 재료 둘인 조합
```

같은 단어가 연속될 차례에는 ambient를 끼워 `클로버 → ambient → 클로버`처럼 보이게 한다. 예전처럼 같은 물건 둘 레시피에서 단어 두 개만 뽑아 판 전체를 잠그지 않는다.

### 첫 밤 이후의 레시피 순서

낮과 밤에는 현재 물건을 활용해 완성에 가까운 레시피를 먼저 찾는다. 입력 다중집합 중 이미 갖춘 비율이 가장 높은 레시피가 우선이며, 선행 합성 결과물을 갖춘 연쇄 레시피도 같은 후보에 들어간다.

완성 가능 레시피만 연속하면 같은 재료가 자주 보여 어색하므로 다음 패턴을 지킨다.

```text
완성 가능성이 높은 레시피 1개
→ 셔플백의 새 레시피 1개
→ 셔플백의 새 레시피 1개
→ 완성 가능성이 높은 레시피 1개
```

두 새 레시피는 완성 후보에서 제외하고, 가능하면 직전 두 레시피와 입력 재료도 겹치지 않는 것을 고른다. 선택지가 부족할 때만 재료 중복을 허용한다. 완성 가능한 후보가 없으면 새 레시피를 고르고, 이후 후보가 생기는 시점에 다시 위 패턴을 시작한다.

### 집중 레시피의 수명

집중 레시피는 다음 중 하나가 일어날 때 바뀐다.

- 관찰된 재료 개수가 이미 입력을 모두 충족했다.
- 입력으로 낼 수 있는 단어 수에 추가 여유 2회를 더한 제안 상한에 닿았다.
- 실제 합성이 성공해 `onMerged()`가 호출됐다.
- 첫 밤·낮·밤 국면이 바뀌었다.

히든이나 이탈로 재료가 사라져도 추가 제안 두 번까지만 허용하는 이유는 한 레시피에 영원히 갇히지 않기 위해서다.

### 현재 재료로 세는 것

GameEngine은 스폰 직전에 다음을 합쳐 `variant id → 개수`로 전달한다.

- 물리 세계에 남아 있는 물건
- 현재 레인에서 내려오는 활성 단어의 기본 물건
- 아직 떨어지지 않은 일반 드롭 대기열

화이트보드 회수 드롭은 곧 사라지므로 개수에 넣지 않는다. 활성 단어는 아직 회수 여부가 확정되지 않았으므로 일단 센다.

## 화이트보드와 결합되는 시간순 흐름

### 1. 판 시작

```text
phase = firstNight
화이트보드 = []
WordSpawner 선호 단어 = []
```

첫 밤에는 RecipeFlow만 단어를 고른다.

### 2. 첫 밤 종료 후 첫 낮 프레임

GameEngine은 다음 순서를 지킨다.

```text
RecipeFlow.setPhase('day')
→ 현재 물건·활성 단어·대기열 관찰
→ RecipeFlow.prepareFocusWords()
→ 집중 레시피와 재료 단어 확정
→ Whiteboard.refill(WORDS, focusedWords)
→ WordSpawner.prefer(whiteboard.words)
```

화이트보드는 집중 레시피 입력을 뺀 나머지 단어에서 세 칸을 채운다. 따라서 첫 화이트보드가 집중 레시피보다 먼저 정해지는 순간은 없다.

### 3. 매 스폰 직전

`prepareFocusWords()`는 현재 집중 레시피가 유효하면 같은 단어 목록을 돌려준다. 레시피가 끝났다면 다음 레시피를 정한 뒤 새 목록을 돌려준다.

GameEngine은 매 프레임 이 목록으로 Whiteboard를 다시 맞춘다.

- 기존 보드 단어가 새 집중 레시피 재료가 되면 즉시 보드에서 빠진다.
- 나머지 유효한 보드 단어는 유지한다.
- 빠진 칸만 새 단어로 채운다.
- 이미 레인에 내려오는 단어라도 새 집중 재료가 되면 회수 표식에서 빠져 일반 드롭으로 돌아간다.

### 4. WordSpawner의 화이트보드 추첨

화이트보드 후보를 `P`, 전체 스폰 후보를 `N`이라고 하면 추가 가중치 몫은 다음과 같다.

```text
extra = P × (4 - 1)
화이트보드 강제 선택 확률 = extra / (N + extra)
```

화이트보드가 3개이고 화면에 활성 단어가 없다면 `9 / 116`, 약 7.8%다. 이 추첨이 실패하면 RecipeFlow가 현재 레시피의 부족한 재료 또는 ambient를 고른다. RecipeFlow가 우연히 화이트보드 단어를 고를 수도 있으므로 싱글의 최종 화이트보드 출현 확률은 고정 4배가 아니다.

화이트보드가 강제로 고른 단어는 RecipeFlow의 다음 값을 바꾸지 않는다.

- 현재 집중 레시피
- 집중 레시피 제안 횟수
- recipe-to-ambient 간격
- RecipeFlow의 마지막 선택 단어

따라서 화이트보드 단어는 집중 흐름 사이에 추가로 끼어드는 단어다.

```text
레시피 재료
→ 화이트보드 단어
→ 레시피 재료
→ RecipeFlow ambient
```

현재 집중 재료는 보드 후보에서 제외되므로 화이트보드가 그 재료를 회수해 합성을 끊지는 않는다. 다만 다른 레시피의 재료는 보드에 들어갈 수 있다.

### 5. 단어를 쳤을 때

#### 보드에 없는 단어

- 조준 위치에 일반 드롭으로 들어간다.
- 드롭 대기열부터 RecipeFlow의 현재 재료 개수에 포함된다.
- 화이트보드는 바뀌지 않는다.

#### 보드에 있는 단어

- 보드에서 해당 단어를 제거한다.
- **같은 집중 레시피 제외 목록**으로 빈 칸을 즉시 보충한다.
- 레인 쪽 회수 판으로 떨어뜨린다.
- 목숨을 깎지 않고 물리 세계에서 제거한다.
- 회수 드롭은 RecipeFlow 재료 개수에 포함하지 않는다.

회수한 단어를 새 후보에서 별도로 금지하지는 않으므로, 집중 재료가 아니라면 낮은 확률로 같은 단어가 다시 보드에 들어갈 수 있다.

### 6. 단어를 놓쳤을 때

놓친 보드 단어는 보드에서 제거되지 않는다. 물건도 생성되지 않고 콤보만 끊긴다. 활성 단어가 화면에서 사라지면 다음 스폰부터 다시 화이트보드 우선 후보가 될 수 있다.

### 7. 낮과 밤 전환

국면이 바뀌면 RecipeFlow는 진행 중인 집중 레시피와 제안 횟수를 초기화한다. 같은 프레임에 새 국면의 레시피를 먼저 확정하고 화이트보드를 다시 맞춘다.

낮과 밤 모두 전체 107개 단어를 쓰므로 국면 전환만으로 보드를 통째로 갈지 않는다. 새 집중 레시피와 겹치는 항목만 교체한다.

## 화이트보드 표시 전환

보드 이미지는 원래 배치 폭의 90%로 그리되 글자 크기는 줄이지 않는다. 글자는 중앙 안전 영역에 배치한다. 목록이 바뀌어도 유지되는 단어는 움직이지 않고, 실제로 빠진 단어와 새로 들어온 단어만 `whiteboardWordChanges()`가 가른다.

- 첫 낮에 보드가 열리면 세 단어를 60ms 간격으로 왼쪽부터 써 내려가듯 드러낸다.
- 단어가 교체되면 이전 글자를 380ms 동안 지우개 자국과 함께 지운다.
- 지우기 시작 300ms 뒤 새 글자를 460ms 동안 왼쪽에서 오른쪽으로 써 내려가듯 드러낸다.
- 연필이나 지우개 물체는 그리지 않고 글자, 번짐, 닦인 자국만 쓴다.
- `prefers-reduced-motion: reduce`에서는 지우기 잔상을 숨기고 새 글자를 즉시 표시한다.

애니메이션 중에도 게임 규칙의 `Whiteboard.words`는 이미 새 목록이다. 연출은 규칙을 늦추지 않으며, 교체가 드문 상태 설명이므로 짧은 지우기·쓰기 전환만 허용한다.

## 난수와 결정론

- RecipeFlow는 판 시드에서 분리한 전용 RNG를 쓴다.
- Whiteboard도 별도 RNG를 쓴다. 현재 GameEngine의 Whiteboard 시드는 `0x5eed`다.
- 화이트보드 추가 가중치 추첨은 WordSpawner의 판 RNG를 쓴다.

따라서 화이트보드 목록을 뽑는 행위는 RecipeFlow 난수열을 밀지 않는다. 다만 화이트보드 우선 추첨이 실제로 실행되면 WordSpawner와 히든 판정이 공유하는 판 RNG는 소비된다. 전체 실행은 결정론적이지만 화이트보드가 없는 실행과 판 난수열까지 같지는 않다.

## 변경할 때 지킬 계약

- `RecipeFlow.pick()` 안에서 처음 집중 레시피를 정하도록 되돌리지 않는다. 화이트보드가 먼저 채워지는 회귀가 생긴다.
- 화이트보드를 `WORDS` 전체로 먼저 채운 뒤 나중에 시각적으로만 숨기지 않는다. `Whiteboard.words`와 `WordSpawner.preferred` 자체에서 집중 재료가 빠져야 한다.
- 보드 회수 후 보충할 때도 동일한 집중 재료 제외 목록을 넘긴다.
- 집중 레시피가 바뀌면 기존 보드 항목 중 겹치는 것만 교체하고 나머지는 유지한다.
- 완성 가능 레시피를 더 자주 호출하더라도 그 사이의 새 레시피 두 개와 재료 비중복 우선을 제거하지 않는다.
- 화이트보드 강제 선택을 RecipeFlow의 recipe/ambient 카운터에 포함하려면 먼저 밀도 측정 기준을 다시 정한다.
- 대전에 적용하려면 셔플백, 현재 집중 레시피, 제안 횟수, 연쇄 시도 상태를 방장 교체 때 동기화해야 한다.

## 최신 실측

완성 가능 레시피 1개와 새 레시피 2개를 교차한 뒤 `2026-08-10`에 10판을 다시 측정했다.

| 지표 | 값 |
|---|---:|
| 판 길이 | 114.0초 |
| 드롭 / 고유 단어 | 43.0 / 34.6 |
| 비레시피 물건 | 판당 7.40개 · 드롭의 17% |
| 3드롭 안의 2재료 조합 | 판당 11.10회 |
| 8드롭 안의 3개 이상 조합 | 판당 1.20회 |
| 실제 합성 | 판당 3.10회 · 못 한 판 10% |
| 합성 밀도 | 100드롭당 7.21회 · 분당 1.63회 |
| 첫 밤 종료 | 10/10판 · 평균 30.9초 |

직전 10판은 판당 합성 3.30회, 100드롭당 7.22회, 분당 1.64회였다. 이번 10판에서는 합성 빈도가 사실상 오르지 않았다. 표본은 작지만 "완성 가능 레시피 우선"만으로 물리 접촉 병목을 풀었다고 볼 근거는 아직 없다. 이 표는 회귀 방향을 보는 기준이며, 다음 밀도 조정 전에는 표본을 늘리거나 집중 재료가 실제 합성으로 이어진 비율을 별도로 잰다.
