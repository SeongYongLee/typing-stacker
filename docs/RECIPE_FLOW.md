# 레시피 중심 스폰과 화이트보드

이 문서는 싱글플레이의 레시피 중심 단어 선택과 화이트보드의 내부 계약을 설명한다. 플레이어가 보는 스테이지·회수·경보 규칙은 [`SINGLEPLAYER.md`](SINGLEPLAYER.md)가 정본이다.

현재 `GameEngine`은 `RecipeFlow`를 기본 `day` 국면으로 사용하지만 `NightFever.start/update`는 연결하지 않는다. 아래 NightFever 설명은 독립 시스템이 제공하는 동작과 테스트 계약이며, 현재 싱글 런타임에서 자동 실행되는 규칙을 뜻하지 않는다. 화면의 낮·밤은 180초 조명 주기다.

관련 코드:

- `src/game/systems/RecipeFlow.ts`
- `src/game/systems/NightFever.ts`
- `src/game/systems/WordSpawner.ts`
- `src/game/core/GameEngine.ts`
- `tests/RecipeFlow.test.ts`
- `tests/NightFever.test.ts`
- `tests/Recall.test.ts`
- `tests/zz-recipe-flow.measure.test.ts`

## 지켜야 하는 규칙

1. `soloStages.ts`가 현재 스테이지에서 등장할 단어 풀을 먼저 제한한다.
2. RecipeFlow는 물리 세계·활성 단어·일반 드롭 대기열을 관찰하고 그 풀 안에서 부족한 재료를 고른다.
3. 화이트보드는 집중 레시피와 별개로 스테이지의 정확한 물건 변형을 최대 3개 목표로 유지한다.
4. 화이트보드 목표와 같은 `ItemVariant.id`가 상자 안에 있을 때만 회수 가능 표시를 켠다.
5. 회수 목표는 WordSpawner에 추가 가중치를 주지 않는다.
6. 회수한 물건은 RecipeFlow가 보는 재료 개수에서 즉시 빠진다.
7. 같은 시드와 같은 관측 상태는 같은 RecipeFlow 순서를 만든다.
8. RecipeFlow는 싱글에만 적용한다. 대전은 별도의 난이도와 랜덤 선택 흐름을 쓴다.

핵심 순서는 다음과 같다.

```text
스테이지 단어 풀 제한
→ 현재 물건·활성 단어·대기열 관찰
→ RecipeFlow가 집중 레시피와 부족한 재료 선택
→ 레인에 스폰

화이트보드: 스테이지 물건 후보 구성
→ 최대 3개 목표 유지
→ 같은 물건이 상자 안에 있을 때만 회수 활성화
```

## 모듈의 책임

### RecipeFlow

현재 집중할 레시피와 그 레시피에서 더 필요한 재료를 정한다.

- 레시피 44개를 직접 레시피 34개와 연쇄 레시피 10개로 분류한다.
- 직접 레시피는 기본 단어만으로 완성할 수 있다.
- 연쇄 레시피는 다른 합성 결과물이 판에 있어야 집중 후보가 된다.
- 직접 레시피의 재료가 아닌 단어는 ambient 무리에 둔다.
- 현재 재료 개수는 외부에서 주입받고 DOM, canvas, Rapier를 직접 알지 않는다.

### NightFever

밤에 여섯 개를 1.8초에 걸쳐 내리고 3초 쉬는 묶음을 만들며 낙하 시각과 x를 정한다.

- 정착한 물건의 윗면 중 최고점에서 1.2m 안을 "상단"으로 본다.
- 상단 물건이 2재료 레시피의 한쪽이면 나머지 한쪽을 표적 주변에 내린다.
- 같은 표적은 묶음마다 한 번만 쓴다. 첫 합성 뒤 남은 재료가 보장 없는 잉여가 되는 것을 막기 위해서다.
- 상단 표적 수는 짝수로 고르고, 남는 칸은 두 재료를 모두 내리는 완성 레시피 쌍으로 채운다.
- 완성 후보가 없으면 무작위 2재료 레시피 세 쌍을 통째로 내린다.
- 묶음은 밤 0초와 4.8초에 열린다. 여섯 개를 0.3초 간격으로 1.8초 동안 내린 뒤 3초 쉰다.
- 다음 9.6초 묶음은 밤 안에 여섯 개를 다 내릴 수 없어 열지 않는다.
- Fever 시계는 입력 드롭의 0.3초 물리 쿨다운과 독립적으로 흐른다.
- x는 물건이 받침대 안에 남는 범위에서 표적 주변 또는 레시피별 무작위 기준점으로 흔든다.
- RecipeFlow·단어·히든과 분리한 전용 RNG를 쓴다.

### Whiteboard

`Whiteboard`는 화면에 표시할 최대 3개의 단어를 보관한다. 현재 GameEngine은 정확한 물건 변형 목록인 `whiteboardTargets`를 직접 구성하고 `Whiteboard.set()`으로 표시 단어를 맞춘다.

- 후보는 현재 스테이지의 기본·히든 물건 변형이다.
- 첫 목록에는 가능하면 히든 목표를 하나 포함한다.
- 목록 전체가 히든이면 일반 후보 하나를 섞어 읽을 수 있는 목표를 남긴다.
- 실제 회수 가능 여부는 단어가 아니라 상자 안의 정확한 변형 id로 판정한다.
- 회수한 칸은 같은 스테이지 후보에서 즉시 보충한다.

### WordSpawner

좌우 레인, 중복 방지, 스폰 간격과 최종 선택 순서를 관리한다.

현재 싱글의 선택 우선순위는 다음과 같다.

```text
RecipeFlow.pick()
→ 최후의 기본 랜덤
```

대전에는 RecipeFlow 선택기를 주입하지 않으므로 기존 랜덤 선택을 유지한다.

### GameEngine

스테이지, RecipeFlow, 화이트보드와 물리를 조립한다.

- 물리 세계, 활성 단어, 드롭 대기열, Fever 예정 재료를 세어 RecipeFlow에 전달한다.
- 물건·단어·대기열 구성이 바뀐 경우에만 RecipeFlow 관측을 다시 계산한다.
- 스테이지가 열릴 때 화이트보드 물건 후보를 한 번 만들고, 회수될 때 빈 칸만 채운다.
- 상자 안에 같은 변형이 있는 목표만 `activeWhiteboard`로 내보낸다.
- 회수 드롭은 RecipeFlow가 보는 재료 개수에서 제외한다.

## RecipeFlow의 분류와 선택

### 직접·연쇄·ambient

| 무리 | 현재 구성 | 의미 |
|---|---:|---|
| 직접 레시피 | 34개 | 모든 재료가 기본 단어로 존재한다 |
| 연쇄 레시피 | 10개 | 입력 중 하나 이상이 다른 합성 결과물이다 |
| 직접 재료 | 65종 | 직접 레시피가 집중할 수 있는 기본 단어 |
| ambient | 42종 | 비레시피 28종 + 연쇄 레시피에서만 쓰이는 기본 재료 14종 |

ambient에 연쇄 레시피의 기본 재료도 넣는 이유는 선행 합성 결과물이 없을 때도 모든 단어가 계속 등장해야 하기 때문이다.

### RecipeFlow·NightFever 모듈이 지원하는 국면별 밀도

| 국면 | 길이 | RecipeFlow 선택 | 직접 낙하·보호 |
|---|---:|---|---|
| 낮 | 20초 | 레시피 선택 2회마다 ambient 1회 | 없음 |
| Night Fever | 10초 | 레시피 선택 3회마다 ambient 1회 | 6개 묶음 2회(총 12개)·하트 무적 |

국면은 단어 낙하 속도와 밀도를 바꾸지 않는다. 밤은 RecipeFlow의 ambient 간격을 늘리는 동시에 NightFever가 0.3초 간격의 물건 묶음을 직접 내린다.

현재 GameEngine은 `RecipeFlow.setPhase()`와 `NightFever.start/update()`를 호출하지 않으므로 실제 싱글 판에서는 `day` 선택 비율만 사용하고 직접 낙하는 실행하지 않는다. 이 표는 두 모듈을 다시 연결할 때 지켜야 할 준비된 계약이다.

### 레시피 순서

낮과 밤에는 현재 물건을 활용해 완성에 가까운 레시피를 먼저 찾는다. 입력 다중집합 중 이미 갖춘 비율이 가장 높은 레시피가 우선이며, 선행 합성 결과물을 갖춘 연쇄 레시피도 같은 후보에 들어간다.

완성 가능 레시피만 연속하면 같은 재료가 자주 보여 어색하므로 다음 패턴을 지킨다.

```text
완성 가능성이 높은 레시피 1개
→ 셔플백의 새 레시피 1개
→ 셔플백의 새 레시피 1개
→ 완성 가능성이 높은 레시피 1개
```

두 새 레시피는 완성 후보에서 제외하고, 가능하면 직전 두 레시피와 입력 재료도 겹치지 않는 것을 고른다. 선택지가 부족할 때만 재료 중복을 허용한다. 완성 가능한 후보가 없으면 새 레시피를 고르고, 이후 후보가 생기는 시점에 다시 위 패턴을 시작한다.

### 집중 레시피의 수명

집중 레시피는 다음 중 하나가 일어날 때 바뀐다.

- 관찰된 재료 개수가 이미 입력을 모두 충족했다.
- 입력으로 낼 수 있는 단어 수에 추가 여유 2회를 더한 제안 상한에 닿았다.
- 실제 합성이 성공해 `onMerged()`가 호출됐다.
- 낮·밤 국면이 바뀌었다.

히든이나 이탈로 재료가 사라져도 추가 제안 두 번까지만 허용하는 이유는 한 레시피에 영원히 갇히지 않기 위해서다.

### 현재 재료로 세는 것

GameEngine은 스폰 직전에 다음을 합쳐 `variant id → 개수`로 전달한다.

- 물리 세계에 남아 있는 물건
- 현재 레인에서 내려오는 활성 단어의 기본 물건
- 아직 떨어지지 않은 일반 드롭 대기열
- 이번 Night Fever에서 아직 떨어지지 않은 예정 재료

화이트보드 회수 드롭은 곧 사라지므로 개수에 넣지 않는다. 활성 단어는 아직 회수 여부가 확정되지 않았으므로 일단 센다. Fever 예정 재료를 미리 세야 RecipeFlow가 같은 재료를 불필요하게 다시 집중하지 않는다.

## 화이트보드와 결합되는 시간순 흐름

### 1. 스테이지 시작

GameEngine은 `featuredEntries(stage)`로 WordSpawner의 단어 풀을 제한한다. 같은 엔트리의 기본·히든 변형과 스테이지가 보장하는 합성 결과를 모아 화이트보드 후보를 만든다.

```text
스테이지 단어 풀 제한
→ 화이트보드 물건 후보 생성
→ 최대 3개 목표 선택
→ 현재 물건·활성 단어·대기열 관찰
→ RecipeFlow 집중 레시피 준비
```

화이트보드는 레시피 집중 단어를 제외하지 않고, WordSpawner에도 선호 단어를 전달하지 않는다. 두 기능은 같은 스테이지 풀을 공유하지만 선택은 독립적이다.

### 2. 재료 구성이 바뀔 때

GameEngine은 물리 세계, 활성 단어, 일반 드롭 대기열, Fever 예약 대기열의 버전을 비교한다. 어느 하나라도 바뀐 경우에만 개수표를 다시 만들고 `RecipeFlow.observe()`와 `prepareFocusWords()`를 호출한다. 아무것도 바뀌지 않은 렌더 프레임에는 재료 개수를 다시 세지 않는다.

### 3. 화이트보드 활성 표시

보드에는 목표 단어가 계속 적혀 있지만, 상자 안에 목표와 같은 `ItemVariant.id`가 있을 때만 활성 표시를 붙인다. 같은 단어에서 나온 다른 히든 변형은 별개의 물건이므로 대신 회수할 수 없다.

### 4. 단어를 입력했을 때

#### 활성 화이트보드 목표

- 물리 세계에서 정확한 변형 하나를 제거한다.
- 손과 회수 물건 연출을 시작한다.
- 회수 횟수와 전체 회수 횟수를 올린다.
- 빈 보드 칸을 같은 스테이지 후보에서 즉시 보충한다.
- 회수 물건은 게임오버 이탈과 RecipeFlow 재료 개수에서 제외한다.

#### 활성 목표가 아닌 단어

- 레인에 같은 단어가 있으면 조준 위치의 일반 드롭으로 들어간다.
- 드롭 대기열에 들어간 순간부터 RecipeFlow의 현재 재료 개수에 포함된다.
- 화이트보드는 바뀌지 않는다.

### 5. 단어를 놓쳤을 때

화이트보드 목표는 유지한다. 레인에서 사라진 단어는 콤보를 끊고 싱글 혼잡 경보를 20% 올리지만 물건은 만들지 않는다. 화이트보드 단어에 별도 스폰 가중치는 없으므로 이후 출현 시점은 RecipeFlow와 스테이지 풀 선택에 따른다.

## 화이트보드 표시 전환

보드 이미지는 원래 배치 폭의 90%로 그리되 글자 크기는 줄이지 않는다. 글자는 중앙 안전 영역에 배치한다. 목록이 바뀌어도 유지되는 단어는 움직이지 않고, 실제로 빠진 단어와 새로 들어온 단어만 `whiteboardWordChanges()`가 가른다.

- 판이 열릴 때 세 단어를 60ms 간격으로 왼쪽부터 써 내려가듯 드러낸다.
- 단어가 교체되면 이전 글자를 380ms 동안 지우개 자국과 함께 지운다.
- 지우기 시작 300ms 뒤 새 글자를 460ms 동안 왼쪽에서 오른쪽으로 써 내려가듯 드러낸다.
- 연필이나 지우개 물체는 그리지 않고 글자, 번짐, 닦인 자국만 쓴다.
- `prefers-reduced-motion: reduce`에서는 지우기 잔상을 숨기고 새 글자를 즉시 표시한다.

애니메이션 중에도 `GameEngine`의 표시 단어 배열은 이미 새 목록이다. 연출은 규칙을 늦추지 않으며, 교체가 드문 상태 설명이므로 짧은 지우기·쓰기 전환만 허용한다.

## 난수와 결정론

- RecipeFlow는 판 시드에서 분리한 전용 RNG를 쓴다.
- NightFever도 레시피·x 선택에 별도 RNG를 쓴다.
- 화이트보드 물건 목표 선택은 판 RNG를 쓴다.

RecipeFlow와 NightFever의 난수열은 화이트보드 선택과 분리되어 있다. 다만 현재 화이트보드 물건 목표는 WordSpawner와 히든 판정이 공유하는 판 RNG를 소비하므로, 보드 후보 수나 선택 횟수를 바꾸면 이후 판 난수열도 달라질 수 있다. 같은 코드·시드·입력 흐름 안에서는 여전히 결정론적이다.

## 변경할 때 지킬 계약

- 화이트보드 목표를 단어 문자열만으로 판정하지 않는다. 같은 단어의 기본·히든 변형을 구분하려면 `ItemVariant.id`가 필요하다.
- 보드에 단어가 적혀 있다는 이유만으로 회수하지 않는다. 상자 안에 정확한 목표 물건이 있을 때만 활성화한다.
- 회수 뒤에는 목표 배열과 표시 단어 배열의 인덱스를 함께 유지한다.
- 화이트보드 목표를 WordSpawner 선호 목록에 다시 연결하려면 스테이지별 출현 확률과 RecipeFlow 제안 횟수 계약을 먼저 정한다.
- 재료 구성이 바뀌지 않은 프레임에서 RecipeFlow 관측을 반복하지 않는다. 물리·단어·대기열·Fever 버전 중 하나가 바뀔 때만 갱신한다.
- 완성 가능 레시피를 더 자주 호출하더라도 그 사이의 새 레시피 두 개와 재료 비중복 우선을 제거하지 않는다.
- Fever x에 `AIM_HALF_RANGE`를 쓰지 않는다. 그 범위는 조준 실패를 허용하려고 받침대 밖까지 열려 있다.
- 같은 상단 물건을 한 묶음에서 두 번 표적으로 삼지 않는다. 첫 재료가 합친 뒤 나머지는 더 이상 보장된 조합이 아니다.
- Fever 낙하에 입력용 `DROP_COOLDOWN_MS`를 적용하지 않는다. 0.2초 리듬이 0.3초 문턱에서 무너진다.
- Fever 예정 재료를 RecipeFlow 관측에서 빼지 않는다. 같은 재료를 단어로 다시 부르는 회귀가 생긴다.
- Fever 표식은 물리 결과를 바꾸지 않고 렌더 스냅샷까지만 전달한다. `TrailField`가 이 표식을 연보라 `sparkle` 꼬리로 바꾼다.
- 자동 물건도 정착 점수·도감·합성 보너스를 기존 물건과 똑같이 받는다. 밤에 놓친 단어는 정확도 점수에서 제외해 Fever 동안 화면 점수가 내려가지 않고, 양수 점수 델타는 연보라색으로 표시한다. 다만 Fever 중 새 방어용 먼지구름·통나무는 만들지 않는다.
- 낮 합성이 연달아 일어나면 통나무 보상 횟수를 대기열에 쌓는다. 이미 낮에 시작한 먼지구름은 밤이 되어도 그대로 완성된다.
- 대전에 적용하려면 RecipeFlow와 NightFever 상태를 방장 교체 때 동기화해야 한다.

## 직전 30개 규칙의 짧은 실측

아래 값은 **밤당 30개였던 직전 규칙**을 `2026-08-10`에 3판·60초로 돌린 결과다. 현재 12개 규칙의 값이 아니다. 장기 밸런스가 아니라 낙하 수와 합성 경로가 실제 엔진에서도 열리는지 보는 연기 시험이다.

| 지표 | 값 |
|---|---:|
| 60초 상한 도달 | 3/3판 |
| 전체 드롭 | 82.7개 (입력 22.7 · Fever 60.0) |
| 실제 합성 | 21.33회 · 못 한 판 0% |
| 합성 밀도 | 100드롭당 25.81회 · 분당 21.33회 |
| 3드롭 안의 2재료 조합 | 4.33회 |
| 8드롭 안의 3개 이상 조합 | 3.67회 |

두 번의 밤에서 정확히 60개가 내려왔고 3판 모두 60초에 살아 있었다. 요청한 폭우와 합성 보장은 확인됐지만 장기 플레이는 더 강해졌다. 180초 10판 재측정 전에는 이 값을 최종 밸런스로 읽지 않는다.

## 직전 Fever 실측

아래 값은 **밤당 6개를 내리던 이전 규칙**의 `2026-08-10` 측정이다. 현재 12개 규칙의 최신 밸런스가 아니며 비교 기준으로만 남긴다. 자동 낙하도 실제 물건이므로 전체 드롭과 합성 밀도에 포함한다.

| 지표 | Fever 전 | **Fever 후** |
|---|---:|---:|
| 판 길이 | 114.0초 | **166.9초** |
| 전체 드롭 | 43.0 | **97.3** (입력 64.3 · Fever 33.0) |
| 고유 단어 | 34.6 | **54.0** |
| 비레시피 물건 | 7.40개 · 전체의 17% | 12.20개 · **입력 드롭의 19%** |
| 3드롭 안의 2재료 조합 | 11.10회 | **16.30회** |
| 8드롭 안의 3개 이상 조합 | 1.20회 | **1.70회** |
| 실제 합성 | 3.10회 · 못 한 판 10% | **19.60회 · 못 한 판 0%** |
| 합성 밀도 | 100드롭당 7.21회 · 분당 1.63회 | **100드롭당 20.14회 · 분당 7.05회** |
| 180초 측정 상한 도달 | — | **90%** |

목표였던 "밤에는 합성이 쉬워진다"는 분명하게 나타났다. 반면 10판 중 9판이 180초 안에 끝나지 않았다. 밤 무적, 안전 x의 무료 재료, 합성 통나무가 함께 판을 크게 늘린 결과다. 이 측정은 회귀 기준이면서 장기 밸런스 리스크다. 세 효과를 나누어 다시 조정하지 않은 채 수치 하나만 낮추면 무엇이 판을 늘렸는지 알 수 없으므로, 다음 조정에서는 Fever 묶음 수·새벽 보호·통나무 기여를 각각 재야 한다.
