# 스테이지 시작 이야기

## 방향

Coffee Talk 공식 소개(https://www.togeproductions.com/project/coffee-talk/)의 ‘작은 공간에서 이야기를 듣고 일상적 행동으로 돕는 경험’을 참고했다.
캐릭터·대사·아트를 복제하지 않고, 분실물 보관소의 손님과 물건을 중심으로 새로 썼다.
비 오는 날 오후부터 밤까지 다섯 장면이 이어지고 첫 장면의 아이와 여행객이 세 번째 장면에서 자매로 재회한다.

1. 교실 — 노란 표지의 스케치북: 미루가 보관소 안에서 언니를 기다리며 빌린 종이에 그림을 그린다.
2. 급식실 — 불도 안 켰는데: 도윤이 우유와 분실물 상자를 가져오고, 실제 계란·프라이팬 합성을 대화로 소개한다.
3. 여행 — 언니가 도착했다: 은재가 동생 미루와 즉시 재회하고 잃어버린 나침반의 특징을 말한다.
4. 체육관 — 다음에는 운동화: 비를 피하는 자매 옆에서 정호가 다음 경기에 쓸 운동화를 찾는다.
5. 밤 — 그림 밖으로 나온 별: 미루가 남긴 그림에서 별가루가 떨어져 밤의 특수 보관함 정리로 이어진다.

각 장면3줄. 자동으로 넘기지 않고 다음/정리 시작/건너뛰기로 조작한다.
PC는 버튼 포커스에서 Enter, 모바일은 터치. Escape는 장면 전체 건너뛰기.
이야기에서 언급한 물건은 장면의 소재이며 별도 강제 회수 퀘스트를 추가하지 않는다.

## 구현

- 스토리 데이터: src/screens/stageStories.ts.
- 화면: StageStoryScreen, 접수대·빗물 창·기존 물건 그림 사용. 새 인물 일러스트/음악은 아직 없음.
- 게임 UI 생성 경계에서 setStageStoriesEnabled(true), 기존 엔진 단위 실험은 기본false로 유지.
- 1~5단계 시작 시 정지. 이야기 중 시간·물리·단어 진행 없음. 완료/건너뛰기 뒤 시작.
- 튜토리얼은 기존 교육 흐름 유지. 일반 게임 시작부터 스토리 적용.
- 재도전마다 다시 보되 언제든 건너뛰기 가능. 무한 모드 계속하기에서 반복하지 않음.
- 모바일은 이야기를 읽는 동안 키보드를 닫고, 완료 터치에서 입력창에 포커스를 돌린 뒤 키보드 안정화를 기다린다.
- 뒤쪽 게임 화면은 inert 처리, 대사 화면 안에서 Tab 순환.

## 검증

엔진의 시간정지·각단계·재시작·튜토리얼·모바일입력대기 검사.
브라우저에서 PC/모바일5단계 각각 다음·건너뛰기·시간정지·입력포커스 확인.
브라우저 에뮬레이션은 실제 iOS/Android 키보드 권한과 애니메이션을 완전히 대체하지 않는다.

## 보관소 도입 연출

각 방문 전에 2.4초 동안 창문, 빗줄기, 접수대와 간판을 보여준 뒤 대화로 이어진다. 같은 하루의 이야기이므로 날짜를 새로 만들지 않고 방문 시간과 손님을 표시한다. 오후와 저녁의 창밖 색감을 구분한다. `이야기 보기`로 즉시 대화에 진입하고 Escape로 전체 이야기를 건너뛸 수 있다.

CSS opacity/transform 애니메이션은 도입 때만 실행하며 대화 중에는 정지한다. React는 단발 타이머만 사용하고 해제 시 정리한다. 동작 줄이기 설정에서는 도입 대기를 생략하고 애니메이션을 끈다. 새 이미지·영상·오디오는 추가하지 않았다.

검증: StageStories 엔진 테스트 4개, 빌드, PC/모바일 5개 스테이지의 자동 전환·즉시 전환·정지·입력 복귀. 브라우저 검사에는 320×240 버튼 노출 및 동작 줄이기도 포함한다.

## 메인 화면에서 입장하기

메인의 `혼자 하기`를 누르면 같은 낮/밤 배경의 양쪽 문짝이 안쪽으로 열리고 실제 게임의 보관소 배경이 드러난다. 원본 그림의 문틀과 문짝을 CSS로 나눠 사용하며 신규 이미지나 프레임 루프는 추가하지 않는다. 1.8초 후 기존 시작 안내로 이어진다. 재시작과 튜토리얼 종료 후 시작에는 입장 연출을 반복하지 않는다.

`entrance` 상태에서는 엔진 시작 타이머를 걸지 않는다. 버튼 또는 Escape로 바로 입장할 수 있고, 동작 줄이기 설정이면 지연을 생략한다. 타이머는 화면 해제 시 정리한다. `node scripts/check-door-entrance.mjs`로 PC/모바일의 입장·자동 완료·건너뛰기·게임 화면 연결·동작 줄이기를 확인한다.

main의 3D 조명 통합 시에는 메인 화면만 문 배경을 유지하도록 `SplashBackdrop.doorway`를 사용한다. 다른 메뉴의 보관소 배경과 공유 조명은 유지하며, 메인에서 입장할 때 그림이 갑자기 문으로 바뀌는 불연속을 막는다.

## 대본 개정

아이의 실내 대기, 언니와의 즉시 재회, 비를 피해 머무는 이유를 명시했다. 미루의 그림은 빌린 종이에 그려지므로 스케치북 회수 성공 여부와 무관하게 이어진다. 도윤의 우유는 직접 가져온 간식이며 사라진 가방 설정은 제거했다. 합성은 물건이 다른 것으로 바뀌는 현상으로 설명하며 원래 모습으로 되돌리는 기능을 약속하지 않는다. 마지막 별가루는 그림에서 나온 물건으로 등장 이유를 마련했다.

이번 수정은 시작 대본과 연출 소재에 적용했다. 특정 손님 물건을 필수 회수하는 목표 및 완료 후 반응은 아직 구현하지 않았다. 실제 성공 여부 없이 물건을 돌려받았다고 단정하는 후속 대사는 없다.

## 시작 신호 순서

일반 게임은 문 열기 → 스토리 → READY(750ms) → START(450ms) → 플레이 순서다. 시작 안내에서 튜토리얼을 선택한 경우에는 기존 튜토리얼 시작 신호를 유지한다. 스토리 건너뛰기도 같은 READY/START를 거치며, 다음 스테이지도 대화 뒤 시작 신호를 보여준다. 신호가 끝날 때까지 엔진의 storyOpen을 유지해 시간과 단어 진행을 막는다.

PC는 START 뒤 입력으로 자동 복귀한다. 모바일은 신호 뒤 `입력하고 시작` 버튼을 눌러 사용자 제스처 안에서 키보드를 연다. 그 뒤 기존 키보드 안정화 대기를 거쳐 플레이한다. 브라우저 검증은 메인의 실제 일반 게임 시작 경로에서 스토리 이전에 READY가 나타나지 않는지, 대화 종료와 건너뛰기 뒤 신호 동안 시간이 정지하는지 확인한다.
