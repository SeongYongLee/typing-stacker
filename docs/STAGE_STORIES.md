# 스테이지 시작 이야기

## 방향

Coffee Talk 공식 소개(https://www.togeproductions.com/project/coffee-talk/)의 ‘작은 공간에서 이야기를 듣고 일상적 행동으로 돕는 경험’을 참고했다.
캐릭터·대사·아트를 복제하지 않고, 분실물 보관소의 손님과 물건을 중심으로 새로 썼다.
비 오는 날 오후부터 밤까지 다섯 손님을 만나고 첫 장면의 아이와 여행객이 마지막에 다시 만난다.

1. 교실 — 아직 그리지 않은 얼굴: 스케치북을 찾는 미루.
2. 급식실 — 한 사람 몫을 더: 기다리는 아이에게 우유를 주려는 도윤.
3. 여행 — 돌아가는 방향: 나침반을 찾고 집에 전화하려는 은재.
4. 체육관 — 응원석에 놓인 것: 손녀의 응원으로 다시 뛴 정호.
5. 밤 — 불을 조금 더 켜두기: 은재와 미루의 재회, 조금 더 열어두는 보관소.

각 장면3줄. 자동으로 넘기지 않고 다음/정리 시작/건너뛰기로 조작한다.
PC는 버튼 포커스에서 Enter, 모바일은 터치. Escape는 장면 전체 건너뛰기.
이야기에서 언급한 물건은 장면의 소재이며 별도 강제 회수 퀘스트를 추가하지 않는다.

## 구현

- 스토리 데이터: src/screens/stageStories.ts.
- 화면: StageStoryScreen, 접수대·빗물 창·기존 물건 그림 사용. 새 인물 일러스트/음악은 아직 없음.
- 게임 UI 생성 경계에서 setStageStoriesEnabled(true), 기존 엔진 단위 실험은 기본false로 유지.
- 1~5단계 시작 시 정지. 이야기 중 시간·물리·단어 진행 없음. 완료/건너뛰기 뒤 시작.
- 튜토리얼은 기존 교육 흐름 유지. 일반 게임 시작부터 스토리 적용.
- 재도전마다 다시 보되 언제든 건너뛰기 가능. 무한 모드 계속하기에서 반복하지 않음.
- 모바일은 이야기를 읽는 동안 키보드를 닫고, 완료 터치에서 입력창에 포커스를 돌린 뒤 키보드 안정화를 기다린다.
- 뒤쪽 게임 화면은 inert 처리, 대사 화면 안에서 Tab 순환.

## 검증

엔진의 시간정지·각단계·재시작·튜토리얼·모바일입력대기 검사.
브라우저에서 PC/모바일5단계 각각 다음·건너뛰기·시간정지·입력포커스 확인.
브라우저 에뮬레이션은 실제 iOS/Android 키보드 권한과 애니메이션을 완전히 대체하지 않는다.
