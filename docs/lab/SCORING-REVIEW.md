# 결과 지표와 점수 보정 검토

## 확인한 현재 규칙

ScoreManager.accuracy = 안착 수 / (안착 수 + 놓친 단어 수), 둘 다0이면1.
최종 점수 = round(원점수 × (0.4 + 0.6 × accuracy)).
정상 입력은 onWordMatched, 안착은 onSettled로 별개다. 회수는 안착 수를 늘리지 않는다.
오타 제출은 콤보·경보에 영향을 주지만 이 분모에는 들어가지 않는다.
따라서 accuracy는 일반적인 타자 정확도가 아니다.

## 같은 입력 결과라도 달라지는 사례

계산을 분리하기 위해 원점수를 각각1000으로 가정한 수학적 예시이며 봇 관측치는 아니다.
정상 입력10회, 놓친 단어1회인 두 판에서:

| 이후 물리 결과 | 현행 accuracy | 최종 점수 |
| --- | --- | --- |
| 안착10개 | 10/11 ≈90.9% | 945 |
| 안착0개 | 0/1 =0% | 400 |

회수·합성으로 정착하지 않는 플레이는 동일한 타자 성공에도 다른 감점을 받을 수 있다.
숫자를 ‘정확도’로 표시하면 플레이어가 잘한 입력을 잘못 평가한 것으로 받아들일 여지가 있다.

## 적용한 표시 개선

결과 화면에서 ‘정확도 82%’ 대신 ‘놓침 감점 −N점’을 표시한다.
N은 rawScore-score의 실제 차이. 감점이 없으면 ‘없음’으로 표시한다.
점수 산식이나 서버에 전송하는 값은 변경하지 않는다.

## 보류한 점수 정책

진짜 입력 성공률을 도입하려면 입력 성공(낙하/회수), 오타 제출, 만료 단어를 별도로 세야 한다.
제출 정확도 = 성공 제출 / 전체 제출, 단어 처리율 = 맞춘 낙하 단어 / (맞춘 낙하 단어+만료).
둘은 다른 지표이며 회수 성공을 넣어 낙하 단어 놓침을 상쇄할지부터 게임 규칙 결정이 필요하다.
성공 제출 수를 바로 현행 산식에 넣으면 기존 점수/순위와의 비교가 달라지므로 지금은 보류한다.
후속 조건: 실제 플레이에서 감점 이해도 확인 → 지표 선택 → 동일 플레이 로그로 점수 차이 계산 → 순위 ruleset 분리 검토.
자동 봇은 오타를 모델링하지 않으므로 현재 측정으로 입력 정확도 정책을 채택할 수 없다.
